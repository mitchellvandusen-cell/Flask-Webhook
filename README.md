# InsuranceGrokBot

**AI-powered SMS and voice bot SaaS platform for insurance agents**

---

InsuranceGrokBot is a multi-tenant, white-label AI bot platform built specifically for insurance agencies. It connects to GoHighLevel (GHL / Lead Connector) CRM via OAuth, intercepts incoming webhook events (new leads, inbound SMS, etc.), and uses xAI's Grok LLM to generate intelligent, context-aware replies — automatically delivered through Twilio as white-label SMS (end clients never see Twilio branding). Each subscribing agency gets a fully isolated bot instance with its own phone numbers, carrier list, prompt configuration, and conversation history. Agency owners can also manage multiple sub-accounts from a single dashboard.

---

## Features

- **Multi-tenant SaaS** — Each agency is fully isolated: separate config, phone numbers, carrier list, conversation history, and AI context.
- **White-label SMS via Twilio sub-accounts** — Outbound messages appear from the agency's own number; Twilio branding is never exposed to end clients.
- **xAI Grok LLM responses** — Context-aware, carrier-specific replies generated by Grok, with per-tenant system prompt customization.
- **Voice AI with real-time Twilio/xAI bridge** — Bidirectional WebSocket bridge (mulaw 8 kHz / PCM 16 kHz) enables live AI voice conversations using xAI's Realtime API.
- **Power dialer with AMD** — Outbound dialing with answering machine detection.
- **GoHighLevel CRM OAuth** — Full OAuth integration with the GHL marketplace; reads contacts, conversation history, and pipeline data.
- **Stripe subscriptions** — Individual, Agency Starter, and Agency Pro plans plus usage-based AI Minutes billing.
- **Discord embedded chat** — Agents can read and reply to Discord channels directly inside the dashboard without leaving the app.
- **Agency management** — Agency owners invite and manage sub-users across multiple GHL locations from one account.
- **External OpenAI-compatible API** — `/api/v1/chat/completions` endpoint with Bearer token auth and Redis-backed rate limiting, so agencies can integrate the bot into their own tooling.

## Stack

| Layer | Technology |
|---|---|
| Web framework | Flask (Python), Gunicorn (4 threads) |
| Database | PostgreSQL via psycopg2 threaded connection pool |
| Background jobs | Redis + RQ (4 parallel production workers) |
| SMS / Voice | Twilio (SMS, sub-accounts, TwiML, Realtime voice) |
| LLM | xAI Grok (text + Realtime voice API) |
| Billing | Stripe (subscriptions + usage-based AI Minutes) |
| CRM | GoHighLevel OAuth (primary); HubSpot, Salesforce, Pipedrive, Zoho, Insureio, Zapier adapters |
| Auth | Flask-Login, Flask-WTF CSRF, itsdangerous tokens |
| Chat | Discord OAuth + Bot API |
| NLP | spaCy `en_core_web_md` (contact fact extraction) |
| Audio DSP | soxr (resampling), scipy (Butterworth EQ), audioop |

## Prerequisites

- Python 3.10+
- PostgreSQL (running and accessible)
- Redis (running locally or via a hosted URL)
- API credentials for:
  - **Twilio** — master account SID + auth token, API key/secret, TwiML App SID
  - **xAI** — API key
  - **Stripe** — secret key, publishable key, webhook secret, price IDs
  - **GoHighLevel** — OAuth client ID + secret (marketplace app)
  - **Discord** — OAuth client ID + secret, bot token (optional, for embedded chat)

## Quick Start

```bash
# 1. Clone the repository
git clone <repo-url>
cd Flask-Webhook

# 2. Copy the example env file and fill in your values
cp .env.example .env
# Edit .env with your actual API keys, DB URL, Redis URL, etc.

# 3. Install Python dependencies
pip install -r requirements.txt

# 4. Download the spaCy language model
python -m spacy download en_core_web_md

# 5. Initialize the database (runs automatically on first start via db.init_db())

# 6. Start the web server
gunicorn main:app --threads 4

# 7. Start background workers (each in a separate terminal)
python worker.py production   # run 4 of these for full throughput
python worker.py demo         # optional: 1 demo worker
```

The app will be available at `http://localhost:8000`.

For local development with webhooks, use a tunneling tool such as ngrok and point your GHL webhook URLs at the tunnel.
